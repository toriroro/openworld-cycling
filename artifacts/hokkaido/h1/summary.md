# 北海道 H1: 札幌を 3D で走る — 2026-11-17

[北海道の草案](../../../docs/history/specs/2026-11-17-hokkaido-draft.md) 7 章の H1。H0 の変換データ（札幌の中心 20.5 × 20.4km）を、ゲームの地形・道路・喫茶店につないだ。

## 動かし方

```bash
npx tsx scripts/hokkaido/build-h0.ts
```

開発サーバーで `/?world=hokkaido`、または起動画面の「北海道（札幌）」。選んだ世界は覚えて、次の起動でも使う。保存（位置・総距離・走った区間・スタンプ）は世界ごとに別。確認は `node scripts/hokkaido-ride-shots.mjs`（結果は `results.json`）。

## したこと

| 所 | 内容 |
|---|---|
| 変換 | 走る道は等級 2・3 を除く（決定 #8）。喫茶店は 1.5km 四方に 1 軒（決定 #9。317 軒 → 59 軒）。地形の Worker 用に格子だけの `terrain.json` |
| 世界の選択 | `src/world-choice.ts`（読み先・保存の鍵・起点・generator・出典）。`RoadClient`・`TerrainStreamer`・`WorldView`・`Towns`・`MapOverlay`・`Game` に渡す。起点は大通公園の東の端 |
| Worker | 地形の Worker と道路の Worker が変換データを読む（`src/workers/hokkaido-load.ts`）。読み終えるまで後の依頼を待たせる |
| 地面 | 土地利用の無い低い平らな所を市街地の色にし、農地・木を置かない。川・湖は草地の色（3D の水面は R2 と共通でまだ無い） |
| 町 | 北海道の世界では結節点に生成の町・街区を作らない（実在の道路の上に生成の街区の道が重なるため）。喫茶店は置く |
| トンネル | H2 で坑口と内壁を作るまで、地形を路面に合わせた切り通しとして描く |
| 出典 | 走行中は左上、起動画面の下、ゲーム内の地図の右上に「地図データ © OpenStreetMap contributors（ODbL）・標高 国土地理院 標高タイルを加工して作成」。押すと元のページ |
| 直した不具合 | 交差点の路面を作る所の `push(...大きな配列)` が、交差点の多い市街地で引数の数の上限を超えていた（交差点が描かれなかった） |

- 大通での軽量画質（844×390）: 三角形 46万、描画命令 333。
- 描画命令が多い（標準の目安 300、軽量 150 を超える）。道路のメッシュが道路の区切りごと（大通の周りで 731 個）にできるため。生成の世界の起点は 161。
- 起点から自動で 60 秒（時間 4 倍）走って 1,268m 進んだ。エラー 0。
- 読み込み（ページを開いてから走れるまで）6.5〜15.5 秒。変換データ約 25MB を、メインスレッドと Worker（4〜5 個）がそれぞれ読む。
- 生成の世界も前と同じに動く（`generated-still-works.png`、突き抜け 0、エラー 0）。テスト 106 件、型の検査、本番ビルドが通る。

`start-odori-*`（大通）、`sosei-*`（創成川通）、`toyohira-cr-*`（豊平川の近く）、`moiwa-*`（藻岩山の観光道路）、`tunnel-*`・`tunnel-mid-*`（小林峠の下。切り通し）、`teine-side-*`、`cafe.png`、`title.png`（世界の選択と出典）、`watch-after-60s.png`。`-chase` は追う視点、`-above` は上から。

## まだの所・確かめていないこと

- 建物が無い。市街地は平らな地面と道路だけ。OSM の建物の外形（H0 の範囲で 42 万棟）に今の 8 つの型を当てる段階が要る（草案 6 章 #5）。
- 描画命令が目安を超える（上）。道路のメッシュを区画ごとにまとめる。
- 川・湖の水面が無い（R2）。トンネルは切り通し（H2）。
- 喫茶店の建物は生成の世界と同じ形（道路の脇に置く）。立ち寄り・スタンプの操作は北海道の世界で人の手では試していない（自動操作で店の前へ飛んだだけ）。
- スマホ・タブレットの実機、Safari、Firefox。メモリ（変換データを Worker ごとに持つ）。
