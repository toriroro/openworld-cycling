# 鉄道 L1（線路の生成と 2D 地図）の確認のまとめ

2026-11-14。[鉄道の草案](../../docs/history/specs/2026-11-14-railway-draft.md) の決定（同日、【要判断】1〜10 をすべて推奨どおり）を受けて、L1 の線路の生成を作った。線路は道路の後に引き、道路は変えない（案 A）。外部の素材・ライブラリは足していない。

## 作ったもの

| 部分 | ファイル | 中身 |
|---|---|---|
| 拠点と路線網 | `src/shared/world/rail.ts` | 24km 格子ごとに重要度のいちばん高い町（標高 400m 未満）を拠点にする。隣の格子の候補が 12km 以内で重要度が高ければ拠点にしない。幹線は拠点どうしの相対近傍グラフ（周囲 5×5 の格子、60km まで、海を 300m 以上渡らない）。支線は拠点の 30% から、8〜22km 先の拠点でない町へ（海沿いを好み、幹線と同じ向きは避ける）。支線の 35% は廃線 |
| 経路探索 | `src/shared/world/rail-route.ts` | 100m 格子の A*（16 方向、1 歩で 45° まで）。勾配 2.5% を超える 1 歩の代わりに、まっすぐ跳んで地面の高い所をトンネル（地面が 12m 以上高い）、低い所を高架（8m 以上低い）で抜ける移動を試す。海・湖の橋は道路と同じ 300m まで |
| 形と縦断 | `rail.ts`、`shape.ts`（点の間隔を引数にした。道路は 2m のまま） | 5m 間隔。最小曲線半径 幹線 300m・支線 200m（道路の整形の後に、線路だけゆるめる回数を足した）。縦断は σ150m で平滑化し、両端と道路との交わりを固定点にして、区間ごとの勾配の上限（2.5%、駅の前後 150m（支線 80m）は 0.3%）を守る列を解く（`solveProfile`）。両立しない固定点は外して数える |
| 駅 | `rail.ts` | 拠点・終点の駅は、町の中心（道路の集まる接続点）から 300〜450m 離れた、平らで水の無い、道路から 50m 以上の所。途中の駅は線から 1km 以内の町・集落、駅どうし 3km 以上（重要度の高い方を残す）。前の行き違いの駅から 8km 以上の駅を行き違いの駅にする。橋・トンネルの中の途中の駅は外す。駅名は町・集落の名前。線の名前は両端の町の 1 字ずつ（「〇〇線」）、支線は終点の町の名前 |
| 道路との交わり | `rail.ts` | 線路の近く（幅 200m の帯）の道路だけを生成して交わりを探す。道路の橋の下を通れる所は「橋の下」、線路がもともと道路より 5m 以上高い所は跨道橋（道路から 6.5m）、それ以外は踏切（線路を道路の高さに合わせる）。高さを合わせられなかった所は、解いた高さで跨道橋・橋の下になればそう分け直し、なお合わない所を「解けない」として数える |
| 橋とトンネル | `rail.ts` | 橋: 地面より 8m 以上高い所が 30m 以上、水の上、跨道橋の前後 12m。トンネル: 地面が 12m 以上高い所が 80m 以上（地形は変えない） |
| データの形 | `src/shared/world/types.ts` | `RailLine`・`RailStation`・`RailCrossing`・`RailSpan`（草案 9 章のとおり）。`Road`・`Junction` は変えていない |
| 2D 地図 | `src/ui/world-map.ts`、`src/workers/world.worker.ts`、`world-protocol.ts`、`src/map-main.ts` | `map.html` だけに描く（ゲームの中の地図には出さない）。線路は黒と白の破線、トンネルは細い破線、廃線跡は点線、駅は四角（行き違いの駅は黄色）、駅名。線路は道路と別の Worker で生成する（道路の読み込みを止めないように） |
| 検査 | `scripts/rail-report.ts`、`scripts/rail-shots.mjs`、`src/shared/world/inspect.ts`（`railHash`）、`tools/world-hash.ts`・`scripts/world-hash-node.ts`・`scripts/cross-engine.mjs`（`rail=1`） | 下の数字 |

`World.region()` にはまだ線路を入れていない（ゲームの道路の読み込みは今のまま）。`GENERATOR_VERSION` は上げていない。廃線跡の自転車道（道路として走れる）と線路の 3D は L2 で、`region()` に入れる時に版を上げる。

起点の葛郷の周り 100km 四方（`scripts/rail-report.ts 50`、結果は `report.json`）:

| 線 | 23（経路が見つからなかった辺 0） |
| 延長 | 幹線 580km、支線 34km、廃線 15km |
| 駅 | 76（拠点 43・行き違い 29・小さな駅 30・終着 3 は線ごとの数） |
| 道路との交わり | 踏切 169、跨道橋 39、橋の下 0、解けない 12（5%）。線 10km あたり 3.3 |

- 端末間の一致（`scripts/cross-engine.mjs`、`rail=1`）: Node・Chrome・Edge・WebKit で線路のハッシュが一致（36km 四方、線 2 本）。Firefox はこの PC では起動できない（今までと同じ）。
- 線路を引いても道路のハッシュは変わらない（テスト）。
- テスト 98 件（鉄道の 3 件を追加: 勾配・曲線半径・駅の間隔、問い合わせの順序によらず同じ・道路が変わらない、縦断の固定点）。
- 2D 地図の画面写真: `map-wide.png`（100km 四方）、`map-origin.png`（葛郷の周り）、`map-station.png`（いちばん近い行き違いの駅、鹿岬）。地図の Worker で 100km 四方の線路がそろうまで 84 秒。

## 見てもらいたい点・決めてもらう点

1. **葛郷の近くに線路が無い。** いちばん近い駅（鹿岬）まで 17km。葛郷（重要度 0.88）は 24km 格子の中で拠点に選ばれず、近くを線も通らない。草案 11 章のとおり、葛郷に駅を置く調整（例: 起点の格子では葛郷を拠点にする）をするか相談したい。
2. **線路の密度が草案の見込みの上限。** 幹線 580km（100km² あたり 5.8km）。北海道の平均（約 3km）の 2 倍。地図（`map-wide.png`）を見て、多ければ辺を減らす規則（草案 3.2）を入れる。
3. 解けない交わり 12 か所（5%）。駅や別の交わりのすぐ近く（150m 以内）の踏切が多い。L2 で 3D にする前に、跨道橋に変える・駅をずらす等で 0 に近づけたい。

## 草案と違えた所

- 経路探索で道路を横切る費用（草案 4.1）は入れていない。探索の範囲（最大 40km 四方）の道路をすべて生成すると遅すぎるため、交わりは見つけた線の近くの道路だけで調べる。踏切の数は 線 10km あたり 3.3。
- 拠点の駅を町の中心から 300〜450m 離した（草案では町の駅としか書いていない）。町の中心は道路の集まる接続点なので、そこで線を終えると踏切の高さが合わない所が多かった（最初の試作で 99 か所のうち 32 か所が解けなかった）。
- 隣の格子の拠点が 12km 以内にあれば拠点にしない規則を足した（最初の試作で 4〜6km の短い幹線ができたため）。

## 確かめていないこと・残っていること

- 線路の 3D、列車、踏切の遮断機、廃線跡の自転車道を走ること（L2・L3）。
- 線路と線路の交わり（平面交差）は調べていない。拠点の駅で線どうしがつながるだけ。
- ゲームの道路の Worker で線路を生成する時の時間（L2 で `region()` に入れる時に測る）。
- スマホ実機。Firefox での一致。
