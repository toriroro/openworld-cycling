# モック仕様（ウェブ版・一人用）

2026-11-13。[概要仕様](2026-11-13-openworld-cycling-overview.md) の P0 と P1 を、ウェブ版の一人用として最初に作る範囲。実装者はこの文書と概要仕様を読めば着手できる。

記号: 【初期値】= 動かして調整してよい数値。【固定】= 変えるなら先に相談する決定。

## 1. モックで確かめること

1. 生成した世界に、走りたくなる道ができるか（線形・勾配・景観の変化）。
2. 地形先行＋道路網の方式が成立するか（破綻のない道路、端末を選ばない一致）。
3. 止まらずに走り続けられるか（生成が走行を止めない、メモリが増え続けない）。
4. 眺めているだけで成立するか。

サーバー、他プレイヤー、トレーナー、iOS アプリは含めない。ただしそれらを後から足せる構造にする（3章の依存規則、概要仕様 9.5）。

## 2. 範囲

| 含む | 含まない |
|---|---|
| 世界生成（高さ、景観3種＋その他、結節点、道路網、橋、立ち寄り地点、地名） | トンネル、川、都市の街路網、天候、季節 |
| 2D 地図（開発用の確認画面を兼ねる） | サーバー、アカウント、位置共有 |
| 3D の地形・道路・植生・建物・海・空のストリーミング | 交通・歩行者・動物 |
| 走行（物理、自動操舵、分岐選択、キーとタッチ）、眺める乗り方 | トレーナー、心拍計、ログ書き出し |
| 喫茶店への立ち寄りとスタンプ、端末内保存と再開 | BGM、連打ダッシュと体力 |
| 環境音（風・路面） | iOS アプリの包装 |
| 横画面基本・縦でも崩れない HUD、画質2段階 | 手動操舵（舵角保持） |

## 3. 技術の前提

### 3.1 道具

- TypeScript、Vite、Three.js（`WebGLRenderer`）、Vitest、Playwright。版は keirin-3D の `package.json` にそろえる（Vite 8 系、three 0.186 系）。Node.js 22。
- UI フレームワークは使わない。3D のキャンバスの上に DOM を重ねる。
- ビルドの変換先は `["es2022", "safari16"]`【固定】。
- 開発サーバー: まず `vite` をそのまま試す。このプロジェクトのパスは `~` を含み、downhill-3D では Vite がファイル配信を拒否したため `scripts/dev.mjs`（ビルド監視＋静的プレビュー）で回避している。keirin-3D は同じ条件で `vite` を直接使っている。拒否された場合だけ downhill-3D の `scripts/dev.mjs` を移す。配信制限を無効にする設定は使わない。
- プレビュー用に `.claude/launch.json` を置く（keirin-3D に例がある）。

- 保存・常時点灯・振動は `platform` を通す。モックでは Web 用の実装だけを書く。
- 概要仕様 9.5 の規則を守る。

## 4. 世界生成（M1）

### 4.1 座標と定数

- 東が +x、上が +y、南が +z。単位は m。世界座標は倍精度。海面は y=0。
- 定数は1つのファイルにまとめる。

| 名前 | 値【初期値】 | 意味 |
|---|---|---|
| `WORLD_SEED` | 6（2026-11-13 決定） | 世界の種 |
| `ORIGIN` | (−32500, 11250)、町「葛郷」`n_-9_2`（2026-11-13 決定） | 起点 |
| `GENERATOR_VERSION` | 4 | 生成結果が変わる変更のたびに上げる。保存データのキーに含める |
| `NODE_CELL` | 4000 | 結節点を1つ置く格子 |
| `ROUTE_GRID` | 50 | 経路探索の格子。世界座標の倍数にそろえる |
| `ROAD_STEP` | 2 | 道路の点列の間隔 |
| `TILE_NEAR` | 256 | 近景タイルの一辺 |

### 4.2 乱数と再現性【固定】

- 乱数は「種と整数の格子番号から作るハッシュ」だけを使う。`Math.imul` による整数の混合。`Math.random` は使わない。
- 結果の分岐に関わる計算（比較・選択・経路探索の費用）は、加減乗除・`Math.sqrt`・`floor`・`abs`・`min`・`max` だけで書く。`sin`・`cos`・`exp`・`pow`・`atan2` などは端末によって末尾の桁が違い得るので、分岐に使う値に通さない。方位角のような「計算結果を保存するだけ」の値には使ってよい。
- 曲線の整形は多項式（smoothstep、2乗）で行う。
- 同じ入力から同じ道路が出ることをテストで固定する（4.10）。

### 4.3 高さ

- `height(x, z)`: 連続な関数。格子ハッシュから勾配を選ぶ勾配ノイズを重ねる。
- 構成【初期値】:

| 層 | 波長の目安 | 役割 |
|---|---|---|
| 大陸 | 150km | 陸と海。全体の標高の土台 |
| 山地の分布 | 60km | 山がちな地域と平らな地域を分ける |
| 山脈 | 20km、尾根型 | 稜線と谷 |
| 丘 | 4km | 中規模の起伏 |
| 細部 | 500m と 60m | 見た目の凹凸 |

- 海岸近くと低地は平らに寄せ、広い平野ができるようにする。標高は海底 −200m 〜 山頂 1,800m 程度に収める。
- 入力をゆがめて（ドメインワープ）直線的な模様を消す。
- `routeHeight(x, z)`: 細部の層を除いた版。道路の経路探索と縦断勾配に使う。
- 川は作らない。海面より低い内陸のくぼ地は海面の高さの湖になる。

### 4.4 景観タイプ

その場で判定する関数にする。保存しない。

| タイプ | 条件の目安【初期値】 |
|---|---|
| 海岸 | 標高 20m 未満で、600m 以内に海がある |
| 平野 | 標高 150m 未満で、周囲の傾斜が 4% 未満 |
| 山岳 | 標高 400m 以上、または周囲の傾斜が 20% 以上 |
| その他（里山） | 上のどれでもない。緑の丘として描く |

境界は重みで連続的に混ぜる（植生の密度や地表の色が急に変わらないように）。

### 4.5 結節点

- `NODE_CELL` の格子ごとに最大1つ。格子内のハッシュで決めた候補 8 点から、定住に向く点（傾斜が小さい、低い、海に近い）を選ぶ。候補がすべて海なら置かない。`ROUTE_GRID` の格子点に寄せる。
- 種類は重要度（ハッシュと平坦さから決める 0〜1）で 町 / 集落 / 分岐のみ に分ける。
- 識別子は格子番号から作る（例 `n_12_-3`）。

### 4.6 道路網

接続の規則【固定】。どちらも「2点と周囲の点の位置だけ」で決まり、どこから計算しても同じ結果になる。

- **主要道**: 相対近傍グラフ。2点 a・b を結ぶのは、a にも b にも ab より近い第三の点がない時。全体が連結になる。
- **枝道**: ガブリエルグラフ（ab を直径とする円の中に第三の点がない）のうち主要道でない辺を、ハッシュで 40%【初期値】だけ採用する。
- 判定には周囲 5×5 格子の結節点を見る。
- 海を 300m 以上またぐ辺は作らない。その結果、島や孤立した地域ができてもよい。

等級【初期値】。辺の両端の重要度と沿線の傾斜から決める。

| 等級 | 幅 | 最大勾配 | 最小曲線半径 | 路面 |
|---|---|---|---|---|
| 幹線 | 7m | 8% | 60m | 舗装 |
| 一般道 | 6m | 10% | 30m | 舗装 |
| 山道 | 4.5m | 12% | 12m | 舗装 |
| 林道 | 3.5m | 15% | 10m | 未舗装 |

### 4.7 経路

1本の道路の経路は次の手順で決める。

1. **探索**: 両端を含む矩形を 1.5km 広げた範囲で、`ROUTE_GRID` の格子上を A* 探索する。16 方向に進める。状態に進行方向を含め、曲がりに費用を掛ける。
   - 費用 = 水平距離 ×（1 ＋ 勾配の費用 ＋ 曲がりの費用）。勾配は `routeHeight` の差から求める。等級の最大勾配を超える移動は高い費用にする（禁止にはしない。必ず道が引けるように）。
   - 海は通れない。ただし 300m 以内で対岸に届く直線は「橋」として高めの費用で通れる。
   - 枝道は、主要道がすでに通っている格子の費用を割り引く。こうすると枝道は主要道に合流し、同じ谷に道が2本並ぶのを減らせる。主要道どうしは互いを見ない（依存を1段に抑えるため）。
2. **整形**: 折れ線を間引き、求心型 Catmull-Rom で曲線にし、等級の最小曲線半径を満たすまで平滑化して、`ROAD_STEP` 間隔に取り直す（downhill-3D の手稲山コース生成と同じ考え方。`docs/teine-course.md`）。
3. **縦断**: 沿線の `routeHeight` を取り、平滑化（ガウス、σ 30m【初期値】）してから、等級の最大勾配に収まるよう前後から制限する。交差点の前後 30m は 3% 以内にする。
4. **橋**: 路面が地面より 6m 以上高い区間が 40m 以上続く所と、水面上の区間を橋にする。切土が深くなる所はそのまま切土にする（トンネルは作らない）。
5. **接続点**: 枝道が主要道に重なった区間は主要道の形をそのまま使い、合流点と分岐点を接続点にする。別々の道路が交わる所も接続点にする。どちらかが橋の区間なら立体交差として接続しない。
6. **重なりの整理**（2026-11-13 追加、`GENERATOR_VERSION` 4）: 主要道は互いを見ずに引くため、同じ結節点から同じ谷へ出る2本が浅い角度で重なって走り、何度も交わることがあった（起点の周り 40km 四方で平面交差 35 か所のうち 34 か所）。結節点を共有する主要道どうしでは、優先の低い方（等級が低い方、同じなら識別子が後の方）を、中心線の距離が2本の幅の半分の和 + 2m 以内で重なって走る区間（40m 以内に離れて交わり直す所を含む）の終わりで切り、優先の高い方へ合流させる。整形した後の枝道の断片も、合流先の道路に同じ意味で重なる区間があれば同じように合流させ直す。

道路1本の結果は両端の結節点だけで決まる（主要道は両端の結節点を共有する主要道に、枝道は周囲の主要道にも依存する）。道路ごとに結果を保存し、`GENERATOR_VERSION` と道路の識別子をキーにする。

### 4.8 データの形

```ts
interface Road {
  id: string;                 // 両端の結節点の識別子から作る
  cls: 0 | 1 | 2 | 3;         // 幹線・一般道・山道・林道
  width: number;
  surface: 'paved' | 'gravel';
  origin: [number, number];   // 点列の基準位置（世界座標）
  points: Float32Array;       // 基準位置からの x, y, z を ROAD_STEP ごとに
  length: number;
  spans: { from: number; to: number; kind: 'bridge' }[];
  name: string;
}
interface Junction {
  id: string;
  x: number; y: number; z: number;
  arms: { road: string; s: number; dir: 1 | -1 }[];   // この接続点から出られる方向
  node?: string;              // 結節点に当たる場合
}
interface Poi {
  id: string;
  kind: 'cafe' | 'viewpoint' | 'pass';
  road: string; s: number; side: 1 | -1;
  name: string;
}
```

- 方位・勾配・曲率は点列から計算する（downhill-3D の `RoadPoint` と同じ項目）。
- 走行位置は「道路の識別子・道のり s・向き」で表す。
- 走行中は、現在地から半径 10km【初期値】以内にかかる道路をすべて生成済みに保つ。接続点はその範囲の道路から求める。
- 将来サーバーで地域単位にまとめて保存する時も、この3つの型を入れ物にする。

### 4.9 立ち寄り地点と名前

- 喫茶店: 道路ごとにハッシュで決める。道なり 15km に1軒程度【初期値】。町の外れ、峠の手前、海沿いで出やすくする。道路の左右どちらかに置く。
- 峠: 道路の縦断の極大で、前後より 100m 以上高い所。
- 展望地: 峠と、海を見下ろす道路沿いの高所。
- 名前: 音節の表からハッシュで合成する日本風の架空名（町・道路・峠・店）。実在の地名と一致したら引き直すための除外表を用意する（中身は後で増やせる形でよい）。

### 4.10 2D 地図と検査

M1 では 3D を作らず、2D 地図で世界の形を確かめる。

- `map.html`: 移動と拡大縮小ができる地図。標高の陰影、景観タイプの色、海、結節点、道路（等級で太さ、勾配で色）、橋、立ち寄り地点を描く。道路を選ぶと縦断図と数値（延長、平均・最大勾配、獲得標高）を出す。後でゲーム内の世界地図の土台にする。
- `scripts/world-report`: 指定範囲（例 40km 四方）の統計を出す。

| 検査 | 合格の目安 |
|---|---|
| 再現性 | 同じ範囲を別の順序・別の起点から生成して、道路の点列が一致する |
| 端末間の一致 | Playwright の Chromium・Firefox・WebKit で同じ範囲を生成し、道路の点列のハッシュが一致する |
| 連結 | 陸続きの範囲で、起点からすべての結節点へ道路でたどれる |
| 勾配 | すべての道路が等級の最大勾配以内 |
| 曲線 | 最小曲線半径を下回る点がない |
| 並走 | 別の道路と 40m 以内で 200m 以上並ぶ区間の総延長を報告する（少ないほど良い。多ければ 4.7 の割引の規則を見直す） |
| 切土・盛土 | 路面と地面の差の分布を報告する。極端な値（30m 超）がない |
| 生成時間 | 道路1本の生成時間の中央値と最大値を報告する |

起点の選定: 15km 以内に海岸・平野（傾斜 3% 未満が 20km² 以上）・山（600m 以上）がそろう場所を種と位置の探索で3つ見つけ、地図の画像を付けて提示する。ユーザーが1つ選び、`WORLD_SEED` と起点を定数に固定する。→ 2026-11-13、候補 A 葛郷（種 6）に決定。検査の結果は `artifacts/m1-summary.md`。

## 5. 3D の表示（M2）

### 5.1 地形

- 世界座標にそろえた正方形タイルを、距離に応じた3段階で描く【初期値】。

| 段 | タイル一辺 | 格子の間隔 | 描く範囲 |
|---|---|---|---|
| 近景 | 256m | 8m | 中景タイルまでの距離が 600m 未満なら近景に分ける（実際は 0.6〜1.6km）。軽量 380m |
| 中景 | 1,024m | 32m | 遠景タイルまでの距離が 2,600m 未満なら中景に分ける（実際は 2.6〜6.7km）。軽量 1,800m |
| 遠景 | 4,096m | 128m | 〜24km。軽量 12km |

（2026-11-13 M2 で調整。分ける距離はタイルの矩形までの距離。子のタイルがそろうまでは親を表示する）

- 段の継ぎ目は縁を下へ伸ばした面（スカート）で隠す。
- 近景は道路の高さに合わせる: 道路端から 4m は路面と同じ高さ、そこから 40m にかけて元の地形へ戻す（downhill-3D の `scenery-jobs.ts` の方式）。地面が路面を突き抜けないことを検査する。
- 地表は傾斜・標高・景観タイプで草・岩・砂・林床を混ぜる。遠景は霞で空の色へ溶かす。
- 海は y=0 の面。
- タイルの頂点計算は Worker で行い、型付き配列を転送する。1フレームに取り付けるタイル数に上限を置く。視界から外れたタイルは数フレームに分けて破棄する。古い依頼の結果は捨てる。Worker が使えない時は同じ処理をメインスレッドで動かす（downhill-3D の `streamed-world.ts` の作法）。

### 5.2 原点の置き直し

描画の原点をカメラ付近に置き、カメラが 2km 以上離れたら 1,024m 単位で置き直す。タイルや道路のメッシュは自分の基準位置からの相対座標（単精度）を持ち、配置だけを倍精度で計算する。

### 5.3 道路

- 道路を 250m ごとのメッシュにし、近くのもの（標準 1.6km、軽量 900m【初期値】）だけ作る。路面、中央線・外側線（等級による）、路肩、谷側のガードレール、橋（床版・欄干・橋脚）。
- 接続点: 道路は接続点の「口」で止め、口の内側を舗装面で埋める。口までの距離は、隣り合う腕の路肩が交わる所に隅切りの接線の長さ（隅切りの半径 幹線 9m・一般道 7m・その他 5m【初期値】）を足したもの（上限 30m）。隣り合う腕の路肩は曲線でつなぎ、路肩の断面と外側線もその曲線に沿わせる。中央線・外側線・ガードレールは口で止める。通り抜ける道路が等級でいちばん高い時は、その中央線を接続点の中も引く。
- 未舗装は別の素材にする。

### 5.4 植生・建物

- 樹木・低木・岩はタイルごとにハッシュで配置し、インスタンス描画する。密度は景観タイプで変える。木は板の画像（近くは3枚、遠くは十字の2枚）、さらに遠くは地表の色で表す。低木と岩は近くだけ立体モデル。（2026-11-13: 近くの木を立体モデルに替えると、板と形・明るさが違い、近づくと別の木に置き換わって見えたため、木は板だけにした）道路と建物の敷地には置かない。
- 町と集落: 結節点の周囲 300〜600m の道路沿いに、敷地を取って建物を並べる。建物は downhill-3D の街区生成（`city-layout.ts`、`sapporo-buildings.ts`）の外壁表現を使う。
  - 実装（2026-11-13）: 町は 300 + 300×重要度 m、集落は 300m。道路の両側に、道路へ向けて幅 8〜14m・奥行き 8〜13m の建物を、すべての道路の路面から 2m 以上離して並べる。中心ほど密で、町の中心（半径の 35% 以内）は 2〜4 階。描く範囲は 標準 2.2km・軽量 1.1km【初期値】
  - 見た目（2026-11-13、ユーザーの決定「生成の形＋写真素材」）: 形は生成し、外壁と屋根に Poly Haven の写真素材（CC0）を貼って建物ごとに色を変える。家（1〜2 階）は切妻か寄棟（軒の出 0.5m、瓦か金属）、サイディングかモルタル、各階の窓（枠・ガラス・桟）、道路側の玄関とひさし、半数ほどに道路沿いのブロック塀。3 階以上は陸屋根とパラペット、道路側のベランダ、1 階の店のガラス面。downhill-3D の窓のシェーダーは使わなくなった
- 喫茶店: 箱形の建物、ひさし、店名の看板、自転車ラック、駐輪スペース。看板の文字は店名だけ。
  - 実装（2026-11-13）: 幅 11m・奥行き 9m・高さ 4.4m。道路の脇に駐輪スペース 7m を挟んで建てる（置けなければ反対側）。描く範囲は 標準 1.6km・軽量 0.9km【初期値】

### 5.5 空と時刻

太陽の位置で空・光・霞の色を変える。モックでは時刻を設定画面で動かせ、既定は午後。影は標準画質のみ。

### 5.6 画質と上限

- 標準と軽量の2段階。軽量は描画解像度を下げ、影なし、植生を半分、描く範囲を縮める。タッチ端末の既定は軽量。
- 目安【初期値】: 標準で三角形 150万・描画命令 300 以内、軽量で 50万・150 以内。JavaScript のヒープは走行距離によらず一定。

## 6. 走行（M3）

### 6.1 物理と入力元

- downhill-3D の `src/physics/bicycle.ts` を移す。120Hz 固定更新、描画と独立。理論値との照合テストも移し、登り勾配の釣り合い速度の照合を足す。
- 推進力は入力元から受け取る【固定】。

```ts
interface PowerSource {
  read(dt: number): { watts: number; brake: number };
}
```

| 入力元 | 内容 |
|---|---|
| 手動 | 押している間、設定した出力（既定 180W【初期値】、50〜400W で変更可）。ブレーキは別のキー・ボタン |
| 自動 | 設定した出力を出し続ける。眺める乗り方で使う |
| トレーナー | モックでは作らない。この型に合わせて後で足す |

- 体重・機材重量・CdA は設定値。初期値は downhill-3D と同じ。
- 路面の転がり抵抗は舗装と未舗装で変える。

### 6.2 道路網上の移動

- 状態は 道路・道のり・向き・左右位置・速度。左側通行で、既定の左右位置は左車線の中央。
- 接続点で別の道路へ進む時は、入る腕の口から出る腕の口まで、左車線から左車線へ曲線で走る（位置と向きを飛ばさない）。カーブ手前の減速はこの曲線も含めて先読みする。
- カーブの手前で自動的に減速する: 先の曲率から上限速度（横加速度 4m/s²【初期値】）を求め、間に合うように制動する。downhill-3D の `curveAhead` の考え方。
- 接触判定・コースアウト・転倒はない。

### 6.3 分岐

- 接続点の 150m 手前から進路の候補を出す。候補ごとに矢印、行き先の地名、距離を表示する。
- 選ばなければ、いちばん直進に近い道へ進む。
- 行き止まりでは自動で折り返す。停止中は U ターンできる。
- 地図で行き先を指定すると、最短経路に沿って分岐を自動で選ぶ。

### 6.4 操作

| 操作 | キー | タッチ |
|---|---|---|
| 漕ぐ | Space | 右下のボタンを押し続ける |
| ブレーキ | Shift | 右下のボタン |
| 分岐の選択 | ← ↑ → | 候補の矢印を押す |
| 左右位置 | A / D | 左下のボタン |
| 視点切替 | C | 画面のボタン |
| 地図 | M | 小地図を押す |
| 眺める乗り方の切替 | V | メニュー |
| 一時停止 | P / Esc | 画面のボタン |

タブが隠れたら一時停止する。

### 6.5 視点

後方・一人称・ドローンの3つ。downhill-3D の `src/render/camera.ts` を移し、地形にめり込まない処理を保つ。

## 7. 立ち寄り・眺める・保存（M4）

### 7.1 喫茶店

- 店の前 30m 以内で停止すると、立ち寄りの表示に切り替わる（店の外観を回る視点。店内は作らない）。表示するのは店名、標高、初めて来た日付、スタンプの数。
- 「出発」で走行に戻る。
- 立ち寄った店はスタンプ帳に残り、再開地点に選べる。

### 7.2 眺める乗り方

- 自動の入力元で走り続ける。進路の方針は 道なり / 未走行の道を優先 の2つ。
- 視点を 20〜40 秒ごとに自動で切り替える。
- 操作がなければ 5 秒で HUD を消す。触れると戻る。
- フレームレートを 30 に抑える設定を持つ。
- 画面を消灯させない（`platform` の常時点灯。使えないブラウザでは何もしない）。

### 7.3 保存

`platform` の保存を通して端末に残す: 現在地（道路・道のり・向き）、総距離、獲得標高、走行時間、走った道路の区間、スタンプ、設定。起動時は前回の続きから始める。保存データに版番号を付ける。

### 7.4 地図

- 小地図: 進行方向が上の円形（downhill-3D の `minimap.ts`）。
  - 実装（2026-11-13）: downhill-3D の `minimap.ts` は座標変換だけだったので、描画は新しく書いた。半径 700m【初期値】、走った区間を太く、喫茶店（立ち寄った店は明るい色）、行き先（円の外なら縁に向き）。押すと世界地図を開く
- 世界地図: M1 の 2D 地図を使う。走った道を強調し、未走行の道は細く描く。立ち寄り地点、現在地、行き先の指定。

### 7.5 音

- downhill-3D の `src/render/audio.ts` から風と路面の合成音を移す。未舗装で路面の音を変える。
  - 実装（2026-11-13）: downhill-3D にあったのは風の音だけだったので、路面の音（舗装はタイヤの走行音、未舗装は砂利の音）は新しく合成した
- 音量と消音の設定。最初の操作で再生を始める。
- BGM は作らない。音の出口は1つのモジュールにまとめ、後から BGM の系統を足せるようにする。
