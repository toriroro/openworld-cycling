# 北海道（実在の地図）概念設計（草案）

2026-11-17 草案。同日、ユーザーの決定: (1) 生成の世界と北海道を並べて置き、起動画面で選ぶ。(3) 喫茶店などの立ち寄り地点は実在の位置だけ使い、名前は一般名にする（後で差し替えられる形にする）。(2) 権利は 3 章で確かめた。残る【要判断】は 9 章。実装はしない。

記号: 【仮定】= 確認なしで置いた前提。【要判断】= 決めてもらいたい点。【初期値】= 動かして調整してよい数値。【未確認】= 実測・試作・原文で確かめていないこと。【概算】= 桁を見るための見積もり。

前提として読んだもの: [概要仕様](2026-11-13-openworld-cycling-overview.md) 3.1・3.2・3.8・9.5・11.1・12・13、[モック仕様](2026-11-13-mock.md) 4.2【固定】、[都市と交通の草案](2026-11-13-urban-and-traffic-draft.md) 12 章（`DistrictPlan`）、`src/shared/world/world.ts`・`terrain.ts`・`types.ts`、`src/workers/world-protocol.ts`、downhill-3D の `docs/teine-course.md` と `scripts/teine-*.mjs`（読み取りのみ）。

## 0. 要点

1. **生成の世界はそのまま残し、北海道を 2 つ目の世界として足す（決定 2026-11-17）。** 起動画面で選ぶ。物理・ライダー・視点・分岐の画面・経路・地図・保存・音・空と天候・交通・建物・街区・農地・植生は 2 つの世界で共通にする。
2. **差し替えるのは 2 か所。** 高さと景観（今の `Terrain`）と、道路・接続点・立ち寄り地点・結節点（今の `World.region()`）。北海道の側は、事前に変換したデータのタイルを読む実装にする（4 章）。
3. **データは国土地理院の標高と OpenStreetMap。** 変換は開発機で事前に行い、ゲームは変換済みのタイルだけを読む。投影の `sin`・`cos` は変換の側に閉じ込め、実行時の `src/shared/world` の規則（モック 4.2【固定】）は守る。
4. **権利（3 章）。** OSM は出典の表示と、配る変換データを ODbL で公開することで使える。国土地理院の標高は、出典と加工の表示に加えて、**一般公開の前に測量法第 30 条の使用承認の申請が要る見込み**（3D の地形を作る使い方が国土地理院の事例集で「使用」に挙がっている）。開発中と、今のパスワード付きの試作は内部の利用に当たると読んでいる【未確認】。
5. **札幌の中心 20km 四方から始める（H0）。** 2D 地図で道路の密度と交差点の間隔を数えてから 3D で走る（H1）。全道は配信の仕組みを作ってから（H3）。

## 2. 世界の並べ方

### 2.1 起動画面

起動画面に世界の選択を足す（「北海道」「生成の世界」）。続きからは最後に走った世界で始める。

### 2.2 差し替える所

| 今の窓口 | 使っている所 | 北海道の実装 |
|---|---|---|
| `Terrain.sample()`・`height()`・`routeHeight()`・`landscape()` | 地形タイル（`terrain-tile.ts`）、2D 地図（`map-tile.ts`）、町（`towns.ts`）、道路の描画（`road-meshes.ts`）、植生 | 標高タイルの双一次補間。景観の重みと水は土地利用・水域のタイルから |
| `World.region(rect)` → 結節点・道路・接続点・立ち寄り地点・交わり | 道路の Worker（`road-client.ts`）、走行、経路、地図 | 道路タイルを読み、同じ型（`Road`・`Junction`・`Poi`・`WorldNode`）で返す |
| `World.prune(keep)` | 走り続けた時の解放 | 読んだタイルを捨てる |
| `DistrictPlan`（街区の入力） | 街区の描画 | OSM の街路と建物の外形から同じ形を作る（都市と交通の草案 12 章で予定していた使い方） |

- 2 つを 1 つの型（`WorldSource`）にまとめ、Worker の `init` で世界の種類を渡す【仮定】。生成の世界の側は今のコードを包むだけで、生成器の版（`GENERATOR_VERSION`）は変えない。
- 保存は世界ごとに分ける（位置・走った区間・スタンプ）。道路の識別子は世界ごとに別物なので混ぜない。
- 生成の世界のデータ取得は無いが、北海道はタイルを読む。読み先は 1 か所で差し替えられるようにする（概要仕様 9.5 の #6 と同じ考え。アプリでは同梱分と配信分を切り替える）。

### 2.3 座標

- 北海道は東西約 450km・南北約 400km。札幌を原点にした 1 つの横メルカトル図法で平面にする【仮定】。原点から 250km 離れた所でも縮尺の誤差は 0.1% 未満【概算】。走行の距離・勾配は実寸のまま（概要仕様 3.2）。
- 世界座標の向きは今の作品に合わせる（downhill-3D の手稲山は東 x・南 z。鏡像の誤りを一度出しているので、変換の検査に「地図の東が画面の東」を入れる）。
- 投影は変換の側で行い、タイルには平面座標で入れる。実行時に三角関数は要らない。

  - 承認後: 成果品に承認番号を書く。成果品を 1 部提出する（ウェブのゲームで何を出すかは【未確認】）。画面の出典は「原則、表示している間は常に見える所」。技術的に難しければ説明のページでもよい。

- 申請が通らない場合の代わりの候補: 30m 格子の全球の標高（Copernicus DEM など）。条件は【未確認】。30m では道路の縦断が粗くなる。

## 4. 変換（開発機で事前に行う）

`scripts/hokkaido/` に置く。元データは `assets-source/hokkaido/`（大きいので git に入れず、取得日・URL・SHA-256 の記録だけ入れる）。出力は世界のタイル。

### 4.1 標高

- 元: DEM5A（無い所は 5B、さらに 10B）。欠けた所は低い解像度で補う（downhill-3D の手稲山と同じ）。海は 0m。
- タイル: 1km 四方、10m 格子（101×101）、0.1m 単位の整数【初期値】。近くの地形は 5m 格子が要るかを H1 で見る。
- 遠景用に 50m・250m 格子の粗いタイルも作る。

### 4.2 道路（走れる道）

OSM の道路から、自転車で走る道だけを道路の網にする。住宅街の細い道まで入れると、札幌の碁盤の目（約 100m ごと）で交差点が続き、150m 手前で出す分岐の候補が成り立たない。

| OSM の種類 | 扱い【初期値】 |
|---|---|
| `trunk`・`primary`・`secondary`・`tertiary`（`motorway` を除く） | 走る道（等級 0〜1） |
| `unclassified`・`track` のうち郊外の物 | 走る道（等級 2〜3。舗装は `surface` から） |
| `cycleway` と、自転車道として印の付いた道（豊平川の河川敷など） | 走る道（等級 4） |
| `residential`・`service`・`living_street` | 見た目だけの街路（街区で描く）。郊外で走る道が足りない所は H0 の数え方で決める |
| `motorway`・`motorway_link`・自転車の通れない道（`bicycle=no`） | 使わない |

- **上り・下りが別の線の道路**（中央分離帯のある道路）は 1 本にまとめ、幅を足す。一方通行は自転車で通れるかの印（`oneway:bicycle`）を見る【仮定】。
- 中心線は点を曲線で補間し、2m 間隔の点列にする（今の `ROAD_STEP`）。
- 縦断は標高を道路に沿って読み、平滑化する（手稲山は道路に沿って 12m のぼかし）。標高データには切土・盛土が入っていないので、勾配の上限を超える所と短い凹凸を数えて報告する。
- **橋**: `bridge=yes` の区間は下の地形を使わず、両端の高さを直線でつなぐ。
- **トンネル**: `tunnel=yes` の区間も同じく両端をつなぐ。今の道路にはトンネルが無いので、描画（坑口・内壁・照明）と、地形を道路に合わせる処理から外す扱いを新しく作る（6 章）。
- 交差点は OSM の点の共有から作る。3 本以上が集まる点を接続点にし、近すぎる接続点（例 20m 以内）はまとめる【初期値】。

### 4.3 水・土地利用・建物・地名・地点

| 種類 | 元 | 行き先 |
|---|---|---|
| 海岸線 | OSM の `natural=coastline` と標高 0m | `Terrain` の水（海） |
| 川・湖 | `waterway=river`・`natural=water` | 水（湖・川）。3D の水面は生成の世界の R2 と共通 |
| 土地利用 | `landuse=farmland`・`meadow`・`forest`、`natural=wood`、`landuse=residential` など | 景観の重み（平野・山・市街）、農地の描画、植生の密度 |
| 建物 | `building=*` の外形と階数 | 今の建物の 8 つの型を外形に当てる。外形の無い市街地は今の街区の生成で補う |
| 地名 | `place=city`・`town`・`suburb`・`village`・`hamlet`（読みは `name:ja-Hira` など） | `WorldNode`（地図と分岐の行き先の名前） |
| 立ち寄り地点 | `amenity=cafe`（位置だけ）、`tourism=viewpoint`、`mountain_pass=yes` | `Poi`。名前は 5.4 |

### 4.4 検査

変換ごとに数えて報告する: 走る道の長さ（等級ごと）、接続点の間隔の分布、勾配の上限を超える区間、道路と地形の段差、橋・トンネルの数、まとめた上り・下りの道路の数、欠けた標高。

## 5. 実行時

### 5.1 タイルの配信

- H0〜H2 は `public/data/hokkaido/` に置いて同梱する。全道（H3）は Cloudflare R2 から配る【仮定】。
- 量【概算】: 全道を 10m 格子にすると約 8 億点。0.1m 単位で 2 バイトなら未圧縮で約 1.7GB。札幌の中心 20km 四方なら約 8MB。道路は 2m 間隔の点列をそのまま送ると全道で数百 MB になるので、OSM の点と高さだけを送り、Worker で 2m 間隔に作り直す。
- 概要仕様 9.5 の #10（素材を外部の CDN から読まない）は、自分の配信先から読むので外れない。アプリでは札幌の周りだけ同梱し、残りは配信【仮定】。

### 5.2 地形

- 近くの地形タイルは、高さ関数の代わりに標高タイルを補間して作る。道路の近くを道路の高さに合わせる処理（今のもの）はそのまま使う。
- 遠景は粗いタイル。

### 5.3 道路・走行

- 道路タイルから `Road`・`Junction` を作る。走行・分岐・経路・小地図・世界地図は変えない。
- 多車線の道路は、決定済みのとおり一番左の車線を走る（都市と交通の草案）。

### 5.4 立ち寄り地点の名前
