# トレーナー連携 概念設計（草案）

2026-11-20 草案。ユーザーが次の主題にトレーナー連携（概要仕様 13 の P2）を選んだ。[都市と交通の草案](2026-11-13-urban-and-traffic-draft.md) 7章で決めた順（U2 → P2）より前に P2 を進めることになるので、その変更を 11 章の 1 として記録する。実装の前に決めてもらう点を【要判断】として挙げる。

2026-11-21、【要判断】1・3〜7 を推奨どおりに決定（1 P2 を U1・U2 より前、3 効きの既定 50%、4 トレーナーでも眺める乗り方の進路を選べる、5 FIT に北海道の世界の緯度・経度を入れる、6 大きい表示は実機で見てから、7 体重・機材は 3.2 の【初期値】）。2（手元の機器）はまだ回答が無い。

記号: 【仮定】= 確認なしで置いた前提。【要判断】= 決めてもらいたい点。【初期値】= 動かして調整してよい数値。【未確認】= 実機・実測で確かめていないこと。

前提として読んだもの: [概要仕様](2026-11-13-openworld-cycling-overview.md) 2.1・4.1〜4.4・6・9.1・9.4・9.5・12・13、[モック仕様](2026-11-13-mock.md) 6.1【固定】・6.3・6.4、`src/sim/power.ts`・`bicycle.ts`・`ride.ts`、`src/platform/index.ts`、`src/game.ts`、`src/ui/hud.ts`、`src/shared/save.ts`。参照元の downhill-3D・keirin-3D に Bluetooth の実装は無い（2026-11-20 に検索した）。

## 0. 要点

1. **入力元の型（モック 6.1【固定】）はそのまま使う。** トレーナーは `PowerSource` の 3 つ目の実装 `TrainerPower` になる。物理（`bicycle.ts`）は変えない。速度は今までどおりゲームの中の勾配・体重・空気抵抗から計算し、トレーナーの車輪の速度は使わない（ゲームの中の自転車の速さと実際の脚の速さを合わせる、一般的な方式）。
2. **対応する機器は 3 種類の標準のサービス。** FTMS（スマートトレーナー。出力・ケイデンスの取得と勾配の指示）、Cycling Power（パワーメーター単体。取得だけ）、Heart Rate（心拍計）。メーカー独自の方式・ANT+・ERG は扱わない（概要 4.2）。
3. **Bluetooth は `platform` 層を通す（概要 9.5 の 5）。** ウェブでは `navigator.bluetooth` を使い、iOS アプリ（P4）ではネイティブのプラグインに差し替える。バイト列の読み書きは端末によらない純粋な関数にし、単体テストで確かめる。
4. **勾配の負荷は「効き」0〜100% で弱められる（概要 4.2）。** 既定は 50%【初期値】。道路の縦断は区間ごとに折れ線なので、そのまま送ると負荷が細かく揺れる。前後の道のりで平均してから送る（4.2）。
5. **体重と機材の重さを設定にする。** 今は 83kg の固定。トレーナーでは体重が登りの速さに直結する（概要 4.1）。
6. **記録は FIT ファイルで書き出す。** 外部の解析ツール・サービスで読めることが P2 の完了条件。ライブラリを足さずに書く（6章）。自動アップロードはしない。
7. **実機での確認はユーザーの手元でしかできない。** この開発環境から Bluetooth の機器は動かせない。代わりに開発用の「仮想トレーナー」（バイト列を作って同じ解析を通す）で、接続から走行までを自動で確かめる。実機で登りの負荷が変わるかは、ユーザーに確かめてもらう（9章）。

## 2. 機器とのやり取り

### 2.1 使うサービスと値

| サービス | 特性 | 読む・書く | 使う値 |
|---|---|---|---|
| FTMS `0x1826` | Indoor Bike Data `0x2AD2`（通知） | 読む | 瞬間の出力（W）、瞬間のケイデンス（0.5rpm 単位）、あれば心拍 |
| | Fitness Machine Feature `0x2ACC` | 読む | シミュレーションモードに対応しているか |
| | Control Point `0x2AD9`（書き込み・応答） | 書く | 制御の要求 `0x00`、開始 `0x07`、シミュレーションの値 `0x11`（風速・勾配 0.01% 単位・転がり抵抗・空気抵抗の係数） |
| Cycling Power `0x1818` | Measurement `0x2A63`（通知） | 読む | 瞬間の出力、クランクの回転の累計と時刻からケイデンス |
| Heart Rate `0x180D` | Measurement `0x2A37`（通知） | 読む | 心拍（8 ビットか 16 ビット） |

- トレーナーが FTMS と Cycling Power の両方を出している時は FTMS を使う（勾配を送れるのは FTMS だけ）。
- パワーメーターとトレーナーを両方つないだ時の出力は、パワーメーターの値を使う【仮定】（一般にパワーメーターの方が正確）。負荷の指示はトレーナーへ送る。
- 出力・心拍の機器は合わせて 2 台まで（トレーナーかパワーメーター 1 台＋心拍計 1 台）【初期値】。

### 2.2 解析と組み立ての関数

`src/sim/trainer/` に、DOM にも Bluetooth にも依存しない関数を置く。

- `parseIndoorBikeData(bytes)`、`parseCyclingPower(bytes, 前回のクランクの値)`、`parseHeartRate(bytes)`
- `encodeSimulation({ grade, crr, cw, wind })`、`encodeRequestControl()`、`encodeStart()`、`parseControlPointResponse(bytes)`

フラグで省かれる項目の並び順を間違えやすいので、項目の組み合わせごとにバイト列を作って単体テストする。

### 2.3 platform 層

`Platform` に `bluetooth` を足す。

```ts
interface BluetoothPort {
  /** 使えるか（ブラウザが対応していない・https でない時は false） */
  readonly available: boolean;
  /** 機器を選ぶ画面を出す（押す操作の中から呼ぶ） */
  choose(kind: "trainer" | "heart"): Promise<BleDevice | null>;
}
interface BleDevice {
  readonly name: string;
  readonly services: readonly string[];
  connect(): Promise<void>;
  disconnect(): void;
  subscribe(service: string, characteristic: string, fn: (bytes: DataView) => void): Promise<void>;
  write(service: string, characteristic: string, bytes: Uint8Array): Promise<void>;
  onDisconnect(fn: () => void): void;
}
```

ウェブの実装だけを作る。開発用の仮想トレーナーは同じ `BleDevice` を実装し、メニューの開発用の入口から選べるようにする（一般の画面には出さない）。

## 3. 走行への入れ方

### 3.1 入力元

| 乗り方 | 推進力 | 分岐 |
|---|---|---|
| 手動 | `ManualPower`（今のまま） | 今のまま |
| トレーナー | `TrainerPower`（最後に受けた出力） | 今のまま（選ばなければ直進、地図の行き先があれば自動）。11 章の 4 |
| 眺める | `AutoPower`（今のまま） | 今のまま |

- トレーナーがつながると、乗り方は「トレーナー」に切り替わる。切れても手動には戻さず、出力 0（惰性で進む）にして「信号なし」を出す。
- 3 秒【初期値】出力の通知が来なければ出力 0 とみなす。
- ブレーキのキー・ボタンは今のまま使える。
- カーブの手前の自動減速（モック 6.2）は今のまま。減速中は物理に渡す出力を 0 にしている（`ride.ts`）が、画面の出力は機器から受けた値を出す。

### 3.2 体重と機材

設定に「体重」（30〜150kg、既定 75kg）と「機材の重さ」（5〜20kg、既定 8kg）を足す【初期値】。`BikeParams.mass` はその和。手動・眺めるにも効く（同じ出力なら体重が軽いほど登りが速い）。CdA は設定に出さない（今の 0.32 のまま）【仮定】。

### 3.3 一時停止とタブ

- 一時停止中・立ち寄り中は、勾配 0 を送る（漕ぎ出しを重くしないため）【初期値】。
- タブが隠れたら一時停止する（モック 6.4）規則は、トレーナーでも変えない。Web Bluetooth の通知は隠れても届くが、走行は進めない。
- トレーナーがつながっている間は画面の常時点灯を入れる（`platform.keepAwake`。今は眺める乗り方で使っている）。

### 3.4 ライダーの動き

トレーナーのケイデンスがあれば、画面のライダーのペダルの回転をそれに合わせる。無ければ今のまま速度から決める。

## 4. 勾配の負荷

### 4.1 送る値

| 値 | 送る中身 |
|---|---|
| 勾配 | ゲームの勾配 × 効き。上り下りとも同じ割合で弱める。−10%〜+20% に収める【初期値】 |
| 転がり抵抗 | 舗装 0.004、砂利 0.011（`CRR` と同じ）。砂利道でペダルが重くなる |
| 空気抵抗の係数 | 0.51 kg/m【初期値】【未確認】（FTMS の仕様書の定義が ½ρCdA か ρCdA か、機器ごとの扱いを確かめていない。合わなければ 0 にして機器の既定に任せる） |
| 風速 | 0 |

- 効きは 0〜100% を 10% 刻みで選ぶ。既定 50%【初期値】（概要 4.2 の例と同じ。ほかのトレーナー用のゲームでも半分前後を既定にするものが多い【仮定】）。速度の計算は効きによらず実際の勾配のまま。
- 効きを下げると、登りで「漕ぐ重さ」は軽くなるが、ゲームの中の速度は上がらない。これは概要 4.2 で決めたとおり。

### 4.2 なめらかにする

道路の縦断は区間ごとの折れ線で、北海道の世界には 10m 格子の標高から来る細かい凹凸がある（北海道の草案 22.1）。送る勾配は、今の位置の前後それぞれ 15m【初期値】の道のりの平均にする。接続点を曲がっている間は、曲がる前の値を保つ。

送る間隔は、変化が 0.1% 以上の時に最短 0.5 秒、変化が無くても 5 秒ごと【初期値】。書き込みの応答を待ってから次を送る（応答待ちの間に来た値は最後の 1 つだけ残す）。

## 5. 画面

- メニューに「トレーナー」の項目を足す: 接続（トレーナー／心拍計）、機器の名前と状態（接続中・信号なし・再接続中）、効き、体重、機材の重さ。
- 走行中の表示に、ケイデンス（rpm）と心拍（bpm）を足す（つないだ機器の値がある時だけ）。出力は 3 秒の平均を出す【初期値】（瞬間値は揺れて読めないため）。
- ブラウザが対応していない時（Safari・Firefox・iOS のブラウザ）は、接続の項目に「このブラウザは Bluetooth に対応していません」と出し、押せなくする。
- トレーナーの前では画面から 1〜2m 離れる。数字を大きくする表示は 7 章の段階の後で見てから決める（11 章の 6）。

文言は操作・状態・事実情報だけにする（CLAUDE.md）。

## 6. 記録と書き出し

### 6.1 記録

- トレーナーがつながってから最初に出力が 0 より大きくなった時に記録を始める。1 秒ごとに 時刻・道のり・速度・出力・ケイデンス・心拍・標高・勾配 を残す。
- メニューの「記録を書き出す」で FIT ファイルを作って保存し、記録を区切る。「記録を消す」で捨てる。
- 走行中の記録は 30 秒ごとに `platform.storage` へ残し、読み込み直しても消えないようにする（1 時間で 3,600 行。詰めた形で 100KB 程度の見込み）【初期値】。

### 6.2 FIT

- 書くメッセージ: file_id、device_info、event（開始・終了）、record（1 秒ごと）、lap、session、activity。スポーツは自転車、種目は仮想の走行（virtual_activity）。
- 位置（緯度・経度）: 北海道の世界は実在の座標を入れられる。生成の世界は入れない。11 章の 5。
- ライブラリを足さずに書く（定義メッセージ・データメッセージ・CRC で 300 行程度の見込み）。ファイルの保存は `platform` に `saveFile(name, bytes)` を足す（ウェブはダウンロード、iOS は共有の画面を後で）。
- 確かめ方: 書いたファイルを自前の読み取りで戻すテストに加え、外部のツール（Garmin の FIT SDK の `FitCSVTool`、GoldenCheetah、Strava など）で読めるかをユーザーに見てもらう。読み取りのライブラリを開発の依存に足すなら先に相談する（CLAUDE.md）。
