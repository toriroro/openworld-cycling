# 鉄道 概念設計（草案）

2026-11-14 草案。同日、【要判断】1〜10 をすべて推奨どおりに決定（1 P3 より前に入れる、2 線路を道路の後に引く、3 ローカル線、4 トンネルは鉄道だけ、5 踏切で止まる、6 世界の時計の時刻表、7 駅の立ち寄りは後で決める、8 L1 を U1 より先、9 廃線跡の自転車道を初めから入れる、10 本数は 7.2 の【初期値】）。これで【要判断】はすべて回答済み。ユーザーの希望の順（田園 → 空と天候 → 車・バス → 鉄道）の 4 番目。鉄道は線形・勾配・踏切を持ち、凍結される地域データに入る（[都市と交通の草案](2026-11-13-urban-and-traffic-draft.md) 7.1）。生成器を変えるので、実装の前に決めてもらう点を【要判断】として挙げる。実装はしない。

## 0. 要点

1. **鉄道は P3 の公開より前に生成器へ入れる必要がある。** 線路は地域をまたいで続く。公開後に足すと、凍結済みの地域（起点の周り。最も走られる所）で線路が途切れる。都市（U1）と同じ理由。
2. **線路は道路の後に引き、道路は変えない（推奨）。** 道路の生成器（モック 4.6【固定】・4.7）と R1 の川はそのまま。線路は道路を見て、踏切・道路を越える橋・道路の橋の下をくぐる、のどれかで交わる。道路の識別子・形・勾配が変わらないので、道路と走った区間・スタンプが壊れない。
3. **手本は北海道・東北のローカル線。** 非電化の単線、1〜2 両の気動車、間隔の広い小さな駅、行き違いのできる駅、木の駅舎や貨車を使った駅舎、雪よけ。町が 3.4km おきにあるので、駅をすべての町に置くと多すぎる。24km の格子ごとに 1 つの「拠点の町」を選び、拠点どうしを結ぶ線を引いて、線の近くの町と集落に駅を置く。
4. **鉄道は道路よりずっと緩い。** 最大勾配 2.5%、最小曲線半径 300m（支線 200m）【初期値】。平地・谷・海沿いを通り、山はトンネルで抜ける。トンネルは鉄道だけに許す（自転車は入らない。入口と出口の坑口だけ描く）。
5. **列車は世界の時計から位置が決まる時刻表で走らせる（推奨）。** 車（端末ごと）と違い、列車は自転車に反応しなくてよいので、全員が同じ列車を見られる。サーバーの計算も通信も要らない。踏切の遮断機も誰の画面でも同じ時に下りる。
6. **踏切で遮断機が下りていたら自転車も止まる（推奨）。** 列車が自転車をすり抜ける絵は車より目立つ。止まる時間は長くて 40 秒ほど【初期値】。設定で止まらないようにもできる。
7. **廃線跡を自転車道にする（推奨）。** 北海道には廃線跡のサイクリングロードが多い。支線の一部を廃線として生成し、R1 の河川敷の自転車道と同じ等級 4 の道路にする。走れる道が増え、この作品の目的（自転車で走る）に合う。凍結される側なので、入れるなら初めから規則に含める。

## 2. 方式の比較: 道路と線路のどちらを先に引くか

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. 線路を道路の後に引く（推奨）** | 道路を今のまま生成し、線路は道路を見て交わり方を決める。踏切では線路の高さを道路に合わせる | 道路の生成器・R1・道路の識別子・保存データが変わらない。今までの検査（M1〜R1）がそのまま効く | 線路の側に制約が集まる（踏切の高さ合わせ、道路の橋の下しかくぐれない）。線路の生成が道路の生成に依存するので、依存の範囲が広くなる |
| B. 道路を線路の後に引く | 線路を先に決め、道路の経路探索で線路を費用に入れ、踏切の前後で道路を平らにし、道路を線路の上に橋で渡す | 踏切の前後が自然になる。道路が線路を越える跨線橋を作れる | すべての道路が引き直しになる。起点の周りの道、走った区間、スタンプ、R1 の自転車道が変わる。道路の生成器【固定】の規則の外の依存が増える |
| C. 同時に解く | 道路と線路を合わせて最適化する | 最も自然 | 「どこから計算しても同じ」（モック 4.6）を守るのが難しい。計算が重い |

推奨は A。道路を固定したまま線路を足せる。線路が道路を越える所は線路の橋（跨道橋）、道路がすでに橋の所は下をくぐる、それ以外の高さが合う所は踏切にする（5 章）。高さの合わない所は線路の縦断を動かして合わせる。

## 3. 路線網

### 3.1 拠点の町

- `RAIL_CELL` = 24km【初期値】の格子ごとに、重要度と平らさから最大 1 つの町を「拠点」に選ぶ。都市と交通の草案 2.2 の都市の核（24km 格子ごとに最大 1 つ）と同じ格子・同じ選び方にそろえれば、都市には必ず駅がある。核の規則を U1 で決める前に鉄道を入れる場合は、鉄道の拠点の規則を核の規則として U1 で使う。
- 海に面した町、川沿いの町を少し好む（港と川沿いに町と鉄道が集まる日本の地方の形）。

### 3.2 幹線と支線

- **幹線**: 拠点どうしの相対近傍グラフ（モック 4.6 の主要道と同じ規則。周囲 5×5 の `RAIL_CELL` を見る）。ただし 2.5% で引けない辺（経路の費用が上限を超える辺）は作らない。そのため幹線の網は全体が連結になるとは限らない。
- **支線**: 拠点から、近くの海沿い・谷の奥の町（拠点でない町）へ行き止まりで延びる線。ハッシュで拠点の 30%【初期値】。終点の駅は行き止まりの終着駅になる。
- 線の名前は「〇〇線」（拠点の町の名前から。名前は音節の表から合成する日本風の架空名。モック 4.9）。
- 密度の目安【未確認】: 24km 格子に拠点 1 つなら、100km 四方（海が 25%）に拠点 12〜17。相対近傍グラフの辺は拠点の数の 1.3 倍ほどなので、幹線の延長は曲がりを含めて 400〜600km、支線 4〜5 本。100km² あたり 4〜6km で、北海道の平均（100km² あたり約 3km）より多い。多すぎれば、幹線を最小全域木＋ハッシュで選んだ少しの辺に減らす。試作で数えて調整する。

### 3.3 途中の駅

- 線から 600m 以内にある町と集落に駅を置く。駅どうしは 3km 以上離す（近い方を間引く。重要度の高い方を残す）。北海道のローカル線の駅間（3〜8km）に近くなる【仮定】。
- 単線なので、拠点の駅と、およそ 8〜12km ごとの駅を「行き違いの駅」（線路が 2 本になる駅）にする。
- 駅の前後 150m（支線 80m）は平ら（0.3% 以内）で、曲線半径 600m 以上にする。

### 3.4 廃線

- 支線のうちハッシュで 35%【初期値】を廃線にする。線路と駅は無く、路盤（盛土・切土・橋）だけが残る。路盤の上に等級 4 の自転車道（舗装、幅 3m、車は通らない）を作る。駅の跡には小さな広場と駅名の碑。
- 自転車道は R1 の河川敷の自転車道と同じく道路網に入り、分岐で選べる。勾配は 2.5% 以内なので、上り下りの少ない長い道になる。
- 廃線跡は道路でもあるので、廃線を入れると道路の数が増える（既存の道路は変わらない）。

## 4. 線形と縦断

数値はすべて【初期値】。

| 項目 | 幹線 | 支線 |
|---|---|---|
| 軌間 | 1,067mm | 同左 |
| 最大勾配（トンネルの外） | 2.5% | 2.5%（短い区間は 3.3%） |
| 最小曲線半径 | 300m | 200m |
| 路盤の幅 | 6m（行き違いの駅で 10m） | 同左 |
| 最高速度（列車） | 85km/h | 65km/h |

### 4.1 探索

- `RAIL_GRID` = 100m【初期値】の格子で A* 探索（道路の 50m より粗い。線路は長く、急な曲がりを許さないため）。16 方向、曲がりの費用は道路より大きくする。
- 費用 = 水平距離 ×（1 ＋ 勾配の費用 ＋ 曲がりの費用 ＋ 水の費用）。2.5% を超える移動は禁止にせず、「トンネル」または「橋」として高い費用で通す。トンネルの費用は長さに比例（坑口の分を足す）、橋は高さと長さに比例。
- 道路を横切る移動に小さな費用を足す（踏切を減らす）。浅い角度（45 度未満）で道路を横切る移動は高くする。
- 川の河原は、道路と同じく高い費用で、渡る時は橋（R1 の `riverCost` と同じ扱い）。川沿いの段丘（河原の縁から 100〜400m）は少し安くする（谷に沿う線になる）。
- 比較と四則演算・`sqrt` だけで書く（モック 4.2【固定】）。

### 4.2 整形と縦断

- 道路と同じ手順（`shape.ts`）: 折れ線を間引き、Catmull-Rom、最小曲線半径まで平滑化。点の間隔は 5m（道路は 2m。線路は曲率が小さいので粗くてよい）。
- 縦断: 沿線の `routeHeight` を平滑化（σ 150m）し、2.5% に収める。次の制約を満たすよう前後から詰める:
  - 駅: 3.3 の平らな区間。
  - 踏切: 線路の高さ = 交わる道路のその点の高さ（5 章）。
  - 道路を越える橋: 線路の高さ ≥ 道路 + 6.5m。
  - 道路の橋の下: 線路の高さ ≤ 道路の橋の下面 − 5.5m。
- 制約を満たせない時は、交わり方を変えて解き直す（踏切 → 跨道橋、の順）。それでも解けない辺は作らない。

### 4.3 橋とトンネル

- 橋: 地面より 8m 以上高い区間が 30m 以上続く所、水面と河原の上、道路を越える所。
- トンネル: 地面が線路より 12m 以上高い区間が 80m 以上続く所。地形（高さ関数）は変えない。線路の点列は地中を通り、描画は坑口の間を描かない。自転車は入らないので、中の形は要らない。
- 切土・盛土: 線路の近く（中心から 5m）は線路の高さに地形を合わせる（道路と同じ扱い。モック 5.1）。法面は道路より長く取る（40m）。

## 5. 道路との交わり

| 交わり方 | 条件 | 道路の側 | 見た目 |
|---|---|---|---|
| 踏切 | 線路と道路の高さの差を 4.2 の縦断で 0 にできる。交わる角度 45 度以上、道路の勾配が前後 15m で 4% 以内 | 変えない（道路データはそのまま） | 遮断機・警報機、線路を埋めた路面、前後の停止線 |
| 跨道橋（線路が上） | 線路が道路より 6.5m 以上高い | 変えない | 線路の桁橋と橋台。道路はその下を通る |
| 道路の橋の下 | 道路がその点ですでに橋（川・谷を渡る橋） | 変えない | 線路が橋の下を通る |

- 道路が線路を越える跨線橋は作れない（道路を変えないため）。案 B を選べば作れる。
- 踏切は道路の接続点にしない（分岐ではない）。道路の点列の上の印として持つ（9 章の `RailCrossing`）。
- 踏切の前後の道路は、線路の幅だけ路面に線路を埋めた形で描く。走行では段差として小さな振動と音を出す（物理は変えない）。

## 6. 駅

- 種類【初期値】: 拠点の駅（駅舎・ホーム 2 面・跨線橋・駅前の広場）、行き違いの駅（ホーム 2 面、構内踏切）、小さな駅（ホーム 1 面、待合室か貨車を使った駅舎）、終着駅（行き止まりの線路、車止め）。
- 駅名は町・集落の名前（駅のある結節点の名前）。結節点から外れた駅は合成した名前。駅名の看板は店の看板と同じく端末のフォントで描く。
- 駅は道路から入れる所に置く: 駅舎の側の 80m 以内に道路があること（無ければ駅の位置を線に沿ってずらす）。
- 立ち寄り地点にするか（駅でスタンプ）は【要判断】（12 章の 7）。

## 7. 列車と運行

### 7.1 出し方

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. 世界の時計の時刻表（推奨）** | 線ごとに時刻表を計算し、列車の位置を「世界の時刻 → 道のり」の関数にする | 全員が同じ列車を見る。通信もサーバーの計算も要らない。踏切が誰の画面でも同じ | 列車は自転車に反応しない（反応しなくてよい） |
| B. 端末ごと | 車と同じく端末ごとに出す | 自転車の近くに列車を出しやすい | 踏切が人によって違う。一緒に走る 2 人で踏切の開け閉めが違う |

車（都市と交通の草案 6.1 で端末ごとに決定）と分けるのは、列車が自転車を避けなくてよいから。線路の上に自転車はいない（踏切は 7.3）。

### 7.2 時刻表

- 時刻は世界の時計（1 日 = 実時間 4 時間）。運行は 5 時〜24 時【初期値】、深夜は走らない。
- 本数【初期値】: 幹線は各方向 1 時間に 1 本（実時間 10 分に 1 本）、支線は 2〜3 時間に 1 本。幹線は 1 日数本の貨物列車。
- 走る時間は線の点列から決める（最高速度、曲線の速度 √(半径 × 0.8)、勾配での加減速、駅の停車 30 秒）。
- 単線のすれ違いは行き違いの駅でだけ起こるよう、各駅での待ち時間を足して時刻表を作る。線ごとに 1 回計算すれば決まる。時刻表は端末で計算する（表示だけなので、端末ごとの末尾の桁の差は問題にならない）。
- 列車の種類【初期値】: 気動車 1〜2 両（普通）、ディーゼル機関車＋コンテナ貨車 10〜15 両（貨物）。形はこの作品で作り、実在の車両・塗装・会社の名前は使わない。

### 7.3 踏切と自転車

- 警報は列車が踏切に着く 30 秒前から鳴り、遮断機は 25 秒前に下り、列車が通り過ぎて 3 秒で上がる【初期値】。
- 自転車の振る舞いは【要判断】（12 章の 5）:
  - a. 止まる（推奨）: 遮断機が下りている、または着くまでに下りる時、停止線で止まる（自動減速と同じ扱い。手動・自動・眺めるのどれでも）。待つのは長くて 40 秒ほど。設定で「止まらない」にできる。
  - b. 止まらない: 信号（都市と交通の草案 6.4 の決定）と同じく通り抜ける。列車が自転車をすり抜ける絵になることがある。
- 車も遮断機の前で止まる（車は端末ごと、遮断機は全員同じ）。
- トレーナー（P2）を使う時は、止まっている間は負荷を 0 にする。

## 8. 見た目と音

- 線路: レール 2 本（金属の光り方）、枕木（コンクリート）、バラスト（砕石）。遠くは地表の色の筋（道路の遠景と同じ扱い）。
- 構造物: 鋼の桁橋とトラス橋（川）、コンクリートの跨道橋、トンネルの坑口、雪よけの柵（防雪柵）、線路際の電柱（通信線。非電化なので架線柱は無い）、距離標、踏切（遮断機・警報機・踏切の看板）。
- 駅: ホーム、上屋、駅舎、駅名標、跨線橋、自転車置き場。
- 素材: 車と同じく形はコードで作る（外部の素材は使わない）。写真素材を足す時は候補と出典を先に示す（CLAUDE.md）。
- 夜: 列車の前照灯・車内の明かり、駅の明かり、踏切の赤い灯。
- 音: 踏切の警報音、列車の走る音（ディーゼルの音、レールの継ぎ目の音）。音は 1 つの音モジュールを通す（概要仕様 9.5 の 7）。警笛は鳴らさない【仮定】（車のクラクションと同じ考え）。
- 2D 地図と小地図: 線路（日本の地図の慣習に近い白黒の破線）、駅、廃線跡（細い点線）。

## 9. データの形

モック 4.8 の型に足す。`Road`・`Junction` は変えない（廃線跡の自転車道は今の `Road` の等級 4 として足す）。

```ts
interface RailLine {
  id: string;                    // 両端の駅の結節点から作る
  kind: 'trunk' | 'branch';
  status: 'open' | 'abandoned';  // 廃線は線路を描かず、路盤と自転車道だけ
  name: string;                  // 〇〇線
  origin: [number, number];
  points: Float32Array;          // 基準位置からの x, y, z を 5m ごとに
  length: number;
  spans: { from: number; to: number; kind: 'bridge' | 'tunnel' }[];
  stations: RailStation[];
  start: string; end: string;    // 端の結節点
}
interface RailStation {
  id: string;
  s: number;                     // 線路の道のり
  name: string;
  node?: string;                 // 町・集落に当たる場合
  kind: 'hub' | 'passing' | 'small' | 'terminus';
  side: 1 | -1;                  // 駅舎の側
}
interface RailCrossing {
  id: string;
  line: string; s: number;       // 線路の道のり
  road: string; roadS: number;   // 道路の道のり
  kind: 'level' | 'over' | 'under';
}
```

- 地域データに `railLines`・`railCrossings` を足す。古い端末は無視できる（概要仕様 10 章の後方互換）。
- `GENERATOR_VERSION` を上げる。道路の結果は変わらない（案 A）。ただし保存データの続きは版が違うと世界座標から始め直す今の作りなので（`src/game.ts`）、道路が変わらない版上げでは道路の位置をそのまま使えるようにする。
- データ量【未確認】: 5m 間隔で 100km の線は 2 万点（240KB）。道路より点が少ない。

## 11. 起点の葛郷への影響

- 案 A なら、葛郷の周りの道路・喫茶店・スタンプは変わらない。
- 葛郷（重要度 0.88。100km 四方の町の重要度は 0.68〜1.00、中央 0.83）が拠点に選ばれるかは規則しだい。選ばれなくても、近くを線が通れば途中の駅になる。L1 の地図を見てから、葛郷に駅を置く調整が要るかを相談する（河川の草案 8 章と同じ扱い）。
