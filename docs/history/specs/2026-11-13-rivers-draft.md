# 河川 概念設計（草案）

2026-11-13 草案。[都市景観と交通の草案](2026-11-13-urban-and-traffic-draft.md) の 7.1（河川を先に検討する、決定 2026-11-13）を受けて書く。実装はしない。決めてもらう点を【要判断】として挙げる。

記号: 【仮定】= 確認なしで置いた前提。【要判断】= 決めてもらいたい点。【初期値】= 動かして調整してよい数値。【未確認】= 実測・試作で確かめていないこと。

前提として読んだもの: [概要仕様](2026-11-13-openworld-cycling-overview.md) 3.3・3.4・3.8、[モック仕様](2026-11-13-mock.md) 4.2・4.3・4.7、`src/shared/world/terrain.ts`・`noise.ts`・`world.ts`・`shape.ts`（生成器 v3）。

## 0. 要点

1. **大きな川は高さ関数に組み込む必要がある。** 川が海まで下り続け、谷と河原を持つには、地形の側を川に合わせて削る必要がある。高さ関数は公開後に変えられない（概要仕様 3.8）ので、P3 より前に入れる。
2. **小さな沢は後から描ける。** 高さ関数を変えず、今の地形の低い所をたどる線として描く。道路と交わる所は暗渠（道の下の管）として見せれば、凍結済みの道路を作り直さずに済む。
3. **推奨は「大河川は高さ関数に、沢は後で描く」の2段（案 C）。**
4. **川の網は、地形の大まかな高さだけから、どこで計算しても同じになるよう局所的に決める。** 2km 格子の各点が「一番低い隣」へ流れる。上流の広さは決まった範囲の中だけで数える。比較と四則演算・`sqrt` だけで書けるので、モック 4.2【固定】を守れる。
5. **技術の山場は「くぼ地」。** 雑音から作った地形には、どの隣より低い点（出口のないくぼ地）ができる。近くの低い点へ水路を切る規則と、切れなければ小さな湖にする規則で扱う。くぼ地がどれだけ出るかは試作で測る。
6. **河川敷の自転車道を道路網に足す。** 都市の近くと下流の大きな川の堤防の上を、車の通らない自転車道（新しい等級）として走れるようにする。概要仕様 3.4 の都市の「河川敷の自転車道」に当たる。
7. **高さ関数が変わると、世界の全体が変わる。** 道路・結節点・起点の葛郷の周り・M1〜M3 の検査結果が作り直しになる。モックを終えてから、都市（U1）より前に入れる案を推奨する。

## 2. 方式の比較【要判断】

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 描くだけ | 高さ関数は変えない。今の地形の低い所を下流へたどって線を引き、近景のタイルで川筋だけ少し削って水面を置く（道路の近くで地形を合わせるのと同じ扱い） | 高さ関数が変わらず、今の世界と道路がそのまま。公開後にも足せる | 雑音の地形はくぼ地が多く、川が途中で途切れる。谷が川の幅に合わず、細い川が広い平地に浮く。道路との交差に橋が無い（凍結済みの道路は川を知らない） |
| B. すべて高さ関数に | 川の網を先に決め、地形を川に合わせて削る。小さな沢まで含める | 谷と川がそろう。道路は川を知ったうえで引かれ、橋が自然に入る | 高さ関数の計算が重くなる。細かい沢まで決めると計算量とデータが増える。公開前に全部を固める必要がある |
| **C. 2段（推奨）** | 大きな川（上流の広さが一定以上）だけ B の方法で高さ関数に入れる。沢は A の方法で後から描く | 大きな川の谷・河原・橋・自転車道が成り立つ。沢は公開後に足せる。高さ関数の負担は大きな川の分だけ | 大きな川と沢の境で作り方が変わる。沢と道路の交わりは暗渠になる |

C を推奨する理由: 体験に効く要素（川沿いの道、長い橋、河口の町、河川敷の自転車道）は大きな川に集まり、どれも凍結されるデータ（道路・橋・結節点）に関わる。沢は景観の細部で、道路との交わりを暗渠で済ませられる。

以下は C を前提に書く。

## 3. 大きな川の網

### 3.1 下地の高さ

- 今の `Terrain.sample` の中で、大陸・山地・山脈・丘を足し、低地を平らに寄せた値（`routeHeight` の元）を「下地の高さ」と呼ぶ。川の網はこの下地から決め、決めた川で削った結果を新しい `routeHeight`・`height` にする。
- 下地 → 川の網 → 削った高さ、の一方向にする。川が自分を決めた高さに影響しないので、循環しない。

### 3.2 流れの向き

- 川の格子 `RIVER_GRID` = 2,000m【初期値】。格子点ごとに下地の高さを取る。
- 各格子点は、周囲 8 点のうち「高さの差 ÷ 距離」が最も大きく下がる点へ流れる。斜めの距離は定数 √2 で割る（三角関数を使わない）。同じ値なら格子番号の小さい方を選ぶ（端末間で結果を変えないための決まり）。
- 海の点（下地が 0 未満）は流れの終点。

### 3.3 くぼ地

どの隣よりも低い格子点（出口なし）は、次の順に扱う。

1. **水路を切る**: 半径 3 格子（6km）以内で、自分より低い点のうち最も近いもの（同じ距離なら最も低いもの）へ向けて流す。途中の格子点の下地を、流れが下り続けるよう削る対象にする。
2. **湖にする**: 3 格子以内に低い点がなければ、その点を湖の底とし、周囲の格子点のうち一番低い縁の高さまで水を張る。湖から先へは流さない（その川は湖で終わる）。

くぼ地がどれだけ出るか、1 で解消できる割合はどれくらいかは【未確認】。試作で測る（7章）。くぼ地が多すぎれば、下地の高さの作り方（低い所を平らに寄せる式など）を見直す。

### 3.4 川の大きさ

- 格子点の「流域」= そこへ流れ込む格子点の数（自分を含む）。1 点が 4km²。
- どこから計算しても同じ結果になるよう、上流は最大 40 格子（80km）の道のりまでしか数えない【初期値】。80km より上流から来る水は数に入らない。日本の川の長さに対して十分と見込む【仮定】。
- 流域が 10 点（40km²）以上の流れを「大きな川」として高さ関数に入れる【初期値】。それ未満は沢（5章）。
- 川幅と河原の幅は流域から決める（目安【初期値】）:

| 流域 | 呼び方 | 水面の幅 | 河原・河川敷を含む幅 | 堤防 |
|---|---|---|---|---|
| 40〜200km² | 中小河川 | 8〜20m | 20〜50m | なし |
| 200〜1,000km² | 河川 | 20〜60m | 60〜200m | 平地で高さ 4m |
| 1,000km² 以上 | 大河川 | 60〜150m | 200〜500m | 平地で高さ 6m |

### 3.5 川の線の形と高さ

- 格子点を結んだ折れ線を、道路と同じ手順（間引き、Catmull-Rom、等間隔に取り直し）で曲線にする（モック 4.7 の 2）。山地では蛇行を少し足す【仮定】。
- 川床の高さ: 下地の高さを川筋に沿って取り、上流から下流へ「直前より高くならない」ように削る。河口で 0 になるよう、最後の区間を緩く下げる。
- 勾配は平地で 0.1〜0.5%、山地で数 % になる見込み【未確認】。急すぎる区間は早瀬として見せる（滝は作らない）。

### 3.6 地形を削る

点 (x, z) の高さを次のように直す。

- 近くの川の線までの距離 d（`Math.sqrt`）と、その位置の川床の高さ b、河原の半幅 w を求める。
- d < w（河原の中）: 高さ = b + 河原の高さ（水面より 0.5〜2m 上、【初期値】）。水面の内側は b。
- w ≤ d < w + 谷の幅: 高さ = 下地の高さと b の間を smoothstep でつなぐ（谷の斜面）。谷の幅は山地で狭く、平地で広い。
- 谷の幅より遠い所は下地のまま。
- 堤防のある区間は、河原の外側に台形の盛り上がりを足す。

使うのは四則演算・`sqrt`・`smoothstep` だけ。モック 4.2【固定】のまま。

### 3.7 計算の局所性と費用

- 点 (x, z) の高さを求めるには、その周りの川の線が要る。川の線は 2km 格子の流れの向きと流域から決まり、流域は最大 80km 上流まで見る。
- 毎回計算すると重いので、川の網を「川のブロック」（例 32km 四方）ごとに計算して覚えておく（`World` が結節点や道路を覚えているのと同じ）。Worker も同じ規則で自分の分を計算して覚える。
- ブロックの境で結果が変わらないよう、流域の数え方は「80km の道のり以内の全上流」という位置だけで決まる規則にする（モック 4.6 の「どこから計算しても同じ」と同じ考え方）。
- 費用の見積もり: 1 ブロックの流域を求めるのに、周り 80km までの格子点（約 1 万点）の下地の高さを1回ずつ取る。下地の高さ1回は勾配ノイズ十数回なので、1 ブロックで数十 ms の見込み【未確認】。高さ関数1回あたりの追加は、近くの川の線を空間索引で引く分。近景タイル1枚（33×33 点）の生成時間がどれだけ増えるかを試作で測る。

## 4. 道路・結節点・都市との関係

### 4.1 道路

- 水の判定（今は `height < 0` を水とし、`world.ts` で橋の判定に使っている）に「川の水面の内側」を足す。これで川を渡る区間は今の規則（水面上の区間を橋にする。16m 未満は盛土で渡す、`WATER_BRIDGE_MIN_LENGTH`）で橋になる。
- 経路探索（モック 4.7）の費用に、川を渡る費用（川幅に比例）を足す。川に直角に近い向きで渡る方を安くする。大きな川は渡る所が限られ、橋が見どころになる。
- 谷底が平らになるので、道路は今より川沿いを通りやすくなる見込み。川と道路が 40m 以内で並ぶ区間は「並走」の検査（モック 4.10）とは別に数える（並ぶのは自然なので、少ないほど良いとはしない）。
- 河原の中には道路を通さない（費用を高くする）。

### 4.2 結節点

- 結節点の候補の得点（`nodes.ts` の `makeNode`）に、川に近いこと・河口に近いことを足す。川沿いの町・河口の港町ができる。
- 河原の中には置かない。

### 4.3 都市（U1）

- 都市の核の得点（都市の草案 2.2）に、大きな川の近く・河口を足す。
- 川が市街を通ると、補助幹線の格子が川で切れ、橋の数が増える。橋の多い市街は日本の都市らしいが、分岐の数も増える。U1 の地図で確かめる。
- 河川敷（河原の広い所）を公園・グラウンドとして描く（5.2）。

### 4.4 河川敷の自転車道【要判断】

- 河原が 60m 以上ある川（3.4 の「河川」以上）で、都市度が 0.2 以上の区間か、河口から 20km 以内の区間に、堤防の上（堤防が無ければ河原の端）を通る自転車道を作る。
- 新しい等級「自転車道」: 幅 3m【初期値】、舗装、最大勾配 5%、車は通らない（交通は歩行者・ランナー・NPC の自転車だけ）。
- 道路網の一部として `Road` に入れ、走れる。川を渡る道路と交わる所（橋のたもと）を接続点にする。堤防の上と橋のたもとの高さの差は、短い坂でつなぐ。
- 依存の順序: 下地 → 川 → 主要道 → 枝道 → 街路 → 自転車道。自転車道は道路が決まってから引く。

## 5. 沢（小さな川）

- 公開後に足せる側。高さ関数は変えない。
- 近景タイルの生成で、川の格子より細かい格子（例 250m）の流れを今の高さから求め、流域が小さい範囲（0.5〜40km²）を沢として描く。くぼ地で途切れたら、そこで地中に消える（伏流）扱いにする【仮定】。
- 道路と交わる所は暗渠（道路の下の管、両側に小さな護岸）として見せる。凍結済みの道路を作り直さない。
- 沢の水面と小さな谷は、近景タイルの頂点で少し削って作る（道路の近くで地形を合わせるのと同じ扱い）。走行の物理は道路の勾配だけを使うので影響しない。

## 6. 見た目

| 要素 | 内容 |
|---|---|
| 水面 | 川の線に沿った帯のメッシュ。流れの向きに動く細かい波をコードで描く（未舗装路の砂利と同じく、素材を足さない）。上流ほど白く泡立つ |
| 河原 | 砂利・草・柳などの低木。景観タイプの地表の混ぜ方に「河原」を足す |

| 河口 | 川の帯を海の面へ広げてつなぐ |
| 湖 | くぼ地の湖は、水面の高さに置いた平面。海と同じ描き方 |
| 遠景 | 大きな川は遠景のタイルにも水面として描く（地形の色で表す） |

描画の上限はモック 5.6 の範囲に収める。川の帯は道路と同じ 250m ごとのメッシュにする。

## 8. 起点の葛郷への影響【要判断】

高さ関数を変えると、次が変わる。

- 結節点の位置（候補の中から得点で選ぶので、川で地形が変われば別の候補が選ばれ得る）。
- 道路の経路・等級・橋、立ち寄り地点（喫茶店・峠・展望地）の位置。町の名前は格子の番号から作る（`placeName(seed, cx, cz)`）ので、同じ格子に結節点が残れば変わらない。
- 起点を選んだ時の数値（15km 以内の海・平野・山の面積）。

結節点の識別子 `n_-9_2` は格子の番号から作るので、同じ格子に町が残れば識別子は同じになる。位置と周りの道路は変わり得る。

| 案 | 内容 |
|---|---|
| a. 格子 `n_-9_2` の町を起点のまま使う（推奨） | R1 の後で葛郷の周りの地図を見せ、海・平野・山（と川）がそろっているかを確かめる。崩れていれば b を相談する |
| b. 起点を選び直す | M1 と同じ探索に「15km 以内に大きな川」を条件に足して選び直す |
